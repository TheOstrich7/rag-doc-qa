## 2. 设计（Design）

### 2.1 文档流

```
PDF  ──PyPDFLoader──▶  Page[]
                        │
                        ▼  normalize_pdf_text()
                        │   • 标题前/后补 \n\n（避免标题与正文粘在一起）
                        │   • 句末标点+换行 → 双换行（给 splitter 段落信号）
                        │   • 标题+正文断行合并（避免中分半句）
                        ▼
                     纯文本（含 \n\n 段落分隔）
                        │
                        ▼  RecursiveCharacterTextSplitter(chunk=400, overlap=80)
                        │   分隔符优先级: \n\n → \n → 。！？； → ，、 → 空格
                        ▼
                     Document[](metadata={source, page, section, chunk_id})
```

### 2.2 选型

| 决策 | 备选 | 选了 | 理由 |
| --- | --- | --- | --- |
| Embedding | OpenAI / HF / fastembed / 自训 | fastembed (默认, auto 降级) | 不想再多一个 API Key 依赖；fastembed 中文效果够用，下载小 |
| 向量库 | FAISS / Chroma / Milvus | FAISS | 轻量、本地、无服务端；题目里点名了 |
| 切分 | tiktoken / Spacy / Recursive | RecursiveCharacterTextSplitter + 中文标点 | 实现简单、跟 LangChain 配合好；中文按标点切语义完整 |
| LLM 协议 | 原生 SDK / langchain-deepseek | ChatOpenAI 指向 DeepSeek base_url | DeepSeek 官方就是 OpenAI 兼容协议；换模型时只改 base_url |
| 检索 | similarity / mmr | MMR（默认） | 制度问答的答案往往集中在某一章，similarity 会给 4 段同义内容；MMR 拿 4 段互补信息 |
| Agent | 硬编码路由 / LangGraph | LangGraph `create_react_agent` | 模型自己决定，符合题目「让 Agent 自己决定」 |
| Web 界面 | FastAPI / Gradio / Streamlit | Streamlit | 上传 PDF + 聊天 = 30 行代码搞定；项目要求「上传 PDF」 |
| 评测 | 全 LLM / 全规则 | LLM-Judge + 规则双轨 | 关键词覆盖率避免 Judge 漂移；LLM Judge 兜底语义 |

### 2.3 不做的事（重要的减法）

- **不**自己写 RAGAS / TruLens 评测——直接调 DeepSeek 跑 LLM-as-Judge，简单可控
- **不**支持流式输出——题目没要求，加进来要把所有 `invoke` 改成 `stream`，收益小
- **不**做用户管理 / 多租户——单进程 CLI
- **不**写数据库——`~/.ragdoc_index` 是 FAISS 文件，足够

## 5. 评估（Evaluation）

跑 `python -m ragdoc.cli eval`：

- 29 题（27 可答 + 2 越界）
- 双路：纯大模型 vs RAG
- 每题 LLM-Judge × 2（正确性 + 忠实度）
- 输出：`results/report.md` / `report.json` / `raw_records.jsonl` / `compare.png`
- 然后 `python scripts/patch_readme.py` 把表回填 README

评测指标设计原则：
- **不**让 Judge 同时评「正确」和「有据」——会鼓励编造高分答案
- **不**用 BLEU/ROUGE——LLM 输出自由文本，n-gram 指标意义不大
- **要**有数字覆盖率——直接看具体数字答出来没有
- **要**有越界题——避免模型"宁可乱说也不拒答"
- **要**有忠实度（仅 RAG）——这是 RAG 的核心价值
